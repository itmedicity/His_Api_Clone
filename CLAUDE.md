# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The Ellider MIS API — the Node/Express backend for a hospital Management Information System serving Travancore Medical College & Hospital (TMCH), Travancore Super Speciality Hospital (TSSH), and a general "QMT" report set. It reads live hospital data from Oracle (patient billing/collection/admission tables) and MySQL (Meliora/BIS/Ellider schemas), and is the API consumed by the `ellider_clone` React front end. No ORM — every query is hand-written SQL/PL-SQL.

## Commands

```
npm start   # nodemon app.js — dev server on $APP_PORT (from .env)
```

There is no lint script and `npm test` is an unimplemented stub (`echo "Error: no test specified" && exit 1`) — there is no test suite in this repository. `GET /health` reports Oracle/MySQL liveness; `GET /pool` (auth required) reports Oracle pool stats; `GET /api/restart` (auth required) manually triggers a pool restart.

## Architecture

- **Entry (`app.js`)**: bootstraps Oracle pools and pings MySQL before listening, wires `helmet`/`compression`/`cors` (origins from the comma-separated `CORS_ORIGINS` env var), sets a 20mb JSON/urlencoded body limit, mounts all routes via `routes/index.js`, then a catch-all 404 and a catch-all error handler that turns **any** uncaught error into a generic `{success: false, message: "Internal Server Error"}` 500. Because of that last handler, a 500 from a route doesn't necessarily mean the route's own logic is broken — see the auth note below.
- **Routing (`routes/index.js`)**: one flat file manually mounting ~50 routers under `/api/*`. Report routes are organized by hospital/grouping with heavy duplication — `misReport` (QMT), `misReportType` (a near-duplicate "QMT Type" variant), `misReportTssh`, `misReportTmch` each reimplement the same collection/income/patient-type report shapes per hospital. **When fixing a bug in one, check the sibling hospital folder for the same code shape** — it's very likely present there too (or already fixed there and not here). Newer report work (commented `LATEST VERSION` markers) lives under `api/Reports/misReportQMT|TMCH|TSSH/` and the newest under `api/Reports/hospitalIncomeReports/{qmt,tmch,tssh}/` — prefer that structure for new report work.
- **Module layering**: each `api/**` module is `*.router.js` (Express `Router`, usually behind `checkToken`) → `*.controller.js` (thin, calls the service, shapes the response) → `*.service.js` (SQL + business logic), with a separate `*.sql.js` for reports built from many queries (see `api/Reports/CollectionReports/CollectionTmc/` for the largest example — 21 queries merged into one report).
- **Response convention**: `{success: 0|1|2, message, data}` — `1` = success with data, `2` = success but empty result ("No Result"), `0` = error. `utls/controller-helperFun.js` exports `controllerHelper`/`controllerGETHelper`/`controllerWithIpNumberInsertHelper`, which wrap this pattern (get a TMC connection, call the service, shape the response, always close the connection) for simpler single-query controllers. Multi-query report controllers (e.g. collection reports) implement the same shape by hand because they need to share one connection/transaction across many queries — see below.
- **Oracle (`config/oradbconfig.js` + `config/oracleExecutor.js`)**: two live named pools, `TMC` (app traffic) and `TMC_CRON` (cron jobs); a third, `KMC`, is fully commented out/disabled. **`api/ProcedureList/procedure.service.js` still calls the now-removed `executeKmc`** and will throw `executeKmc is not a function` if that route is hit — left unchanged pending a decision on it (see `version.md`). Runs in Thick mode (`oracledb.initOracleClient()`), pinned to `oracledb@6.9.0` because the target DB predates what Thin mode / newer Thick-mode client requirements support — don't bump past a Thick-mode-compatible version without also upgrading the Oracle Client on the host. `executeTmc`/`executeCron` wrap a single query with retry-on-recoverable-error (ORA-03113 etc., see `RETRY_ERRORS`) that restarts just the affected pool and retries up to 3 times. Report controllers that run many queries per request instead call `getTmcConnection()` directly and share that one connection — this is intentional (one transaction/connection per request for multi-query reports) but means those queries **don't** get `executeTmc`'s auto-retry-on-disconnect behavior. Pools also self-restart on a rolling schedule (`scheduleRestart`, default every 3 hours), retried every 5 minutes if the pool is still busy rather than silently skipped for a full cycle.
- **MySQL (`config/mysqldbconfig.js`)**: three named pools — `meliora`, `bis`, `ellider` — via `mysql2/promise`. Use `query(poolName, sql, params)` for a single statement or `transaction(poolName, queries)` for a multi-statement transaction; `acquireLock`/`releaseLock` provide MySQL advisory locks for cron-safe singleton work (see the usage examples in the file's own trailing comment block).
- **Auth (`auth/jwtValidation.js`)**: `checkToken` accepts two token schemes — `Bearer <token>` verified against `JWT_KEY` (this API's own login), or `Token <token>` verified against `SECRET_KEY_MEL` (tokens issued by the separate Meliora system). **Known bug**: it reads `req.get("authorization")` and immediately calls `.startsWith()` on it with no null check — a request with no `Authorization` header throws, which is caught by `app.js`'s catch-all handler and returned as a generic 500 instead of 401/403. Don't assume a 500 on an unauthenticated request means the target route itself is broken.
- **Cron jobs (`cron-jobs/`)**: `cron.controller.js` schedules its jobs (`cron.schedule(...)`) as a **module-load side effect**, not inside a route handler. `routes/index.js` mounts `cron.router` on `/api/cronjob` in a commented-out line, but the `require("../cron-jobs/cron.router")` above it is *not* commented out — requiring that module still requires `cron.controller.js`, which still runs its `cron.schedule()` calls at startup. **The cron jobs are live even though the HTTP route that would let you inspect/trigger them manually is not.** `cron-jobs/cron.controller-bisbkp.js` and `cron-jobs/CronLogger-Bkp.js` are superseded backups, not wired into anything — don't treat them as live code.
- **Versioning**: commit messages follow Conventional Commits (`feat:`, `fix:`, `BREAKING CHANGE`/`!:`). `.github/workflows/version-bump.yml` runs `scripts/bump-version.js` on every push to `main`, auto-bumping `package.json`'s version and appending a categorized entry to `version.md` (feat → minor, fix/other → patch, breaking → major). Keep using these prefixes so that automation keeps working. `version.md` is a curated changelog with rationale — check it (not just `git log`) for context on why past changes were made.

## Known issues (see `version.md` for more)

- `config/oradbconfig-old.js` is a superseded version of `config/oradbconfig.js`, not required anywhere — don't confuse the two.
- `KMC` Oracle pool is disabled but still referenced by `api/ProcedureList/procedure.service.js` (see above).
- `checkToken` 500s (instead of 401) on a missing/malformed `Authorization` header (see Auth above).
- Heavy duplication across the QMT/QMT-Type/TSSH/TMCH report variants — a fix in one is very likely needed in the others too.
